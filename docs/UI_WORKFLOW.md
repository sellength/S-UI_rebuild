# UI 工作流约束

本文档记录 S-UI 分布式重构中的 UI 设计与出图流程。

## 1. 基本原则

- UI 相关讨论、布局方案、视觉出图和前端重构，必须先使用项目可用的 UI / UX / Product Design skill 或本文件定义的流程。
- 禁止直接使用通用图片生成工具生成后台 UI 方案。
- 后台管理页面需要可落地、可讨论、可实现；优先产出结构准确的线框稿，而不是风格化概念图。

## 2. 推荐流程

1. 先确认页面目标、主要用户、核心任务和需要避免的误导。
2. 先输出信息架构：模块、列表、表单、状态、主要操作。
3. 再输出低保真布局：优先使用 SVG、HTML mockup 或真实前端页面。
4. 用户确认信息结构后，再进入真实前端实现。
5. 实现后用浏览器检查明暗主题、响应式、按钮状态、文案、空状态和错误提示。

## 3. 出图规则

- 可以出图，但必须是可控的 UI 线框稿或基于真实 DOM / 样式的页面原型。
- 不使用通用生图工具直接生成后台 UI。
- 如果需要视觉参考，应先基于当前页面截图、现有组件、设计约束整理布局，再生成 SVG/HTML mockup。
- 输出图必须服务于布局讨论，不能出现与当前产品无关的海报、插画、教学图或营销图。

## 4. 集群管理页面约束

- 节点状态要区分内部状态和外部状态：
  - 内部状态：Agent、Sing-box、配置版本、最后心跳。
  - 外部状态：DNS、端口、TLS、协议可用性。
- 大量节点场景优先使用表格或紧凑列表，不使用大面积散落状态块。
- 配置向导应作为弹窗、抽屉或右上角入口，不长期占据主内容区域。
- 错误提示应尽量使用底部横条或可展开日志入口，不遮挡核心操作。
